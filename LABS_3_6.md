# Реализация лабораторных №3–6

## №3. Сигнатурный анализ и файловый сканер

Цель — находить известные тестовые угрозы по SHA-256. Задачи выполнены в `signatures.py` и `scanner.py`: потоковое чтение файла, локальная JSON-база с добавлением/удалением/заменой сигнатур, рекурсивный обход, исключения, обработка ошибок. При первом запуске добавляется только безвредная тестовая сигнатура EICAR. Результат содержит путь, имя, хэш, статус, угрозу и время. Алгоритм: вычислить SHA-256 → проверить базу → передать файл дополнительным анализаторам → вернуть `ScanResult`. Пример работы: создать безвредный файл, добавить его хэш командой `signature add`, затем выполнить `scan`. Вывод: тестовая сигнатура обнаруживается без загрузки большого файла целиком в память.

## №4. Эвристика, процессы и файловые события

Цель — отмечать неизвестные подозрительные объекты и наблюдать изменения. `heuristic.py` проверяет расширение, формат, двойное расширение, опасные строки, энтропию и сочетания признаков. Каждое правило имеет вес; суммарный балл сравнивается с порогом чувствительности. `behavior.py` получает процессы через psutil, сравнивает снимки и отмечает запуск из временного каталога и подозрительную цепочку «офисное приложение → оболочка». `filesystem.py` фиксирует создание, изменение и удаление файлов между опросами, передаёт события в ядро. Пример: файл `invoice.pdf.exe` с безопасной тестовой строкой `powershell -enc` вызывает несколько эвристических правил. Вывод: модуль даёт объяснимые находки; опрос не гарантирует обнаружения файлов, существовавших только между двумя снимками.

## №5. Пассивный сетевой анализ

Цель — наблюдать соединения и пакеты без вмешательства. `network.py` получает интерфейсы и соединения через psutil, извлекает метаданные IP/TCP/UDP/DNS из пакетов Scapy и оценивает частоту соединений, число адресов, повторы и DNS-запросы. Локальные списки подозрительных IP и доменных суффиксов настраиваются через `network_rules`. Пример теста: имитация соединения к адресу из списка создаёт находку `Network.SuspiciousIP`. Вывод: правила работают на синтетических событиях; реальный захват требует разрешений ОС и не проходил аппаратные испытания.

## №6. Реагирование и комплексное тестирование

Цель — связать модули и безопасно реагировать. `core.py` связывает сканер, мониторинг, журнал и карантин; `events.py` хранит события JSONL; `quarantine.py` хранит шифрованную AES-256-GCM копию, подтверждает действие и проверяет целостность при восстановлении. `ui.py` предоставляет нативное окно на Qt Widgets, `cli.py` — терминальные команды, `report.py` — JSON/CSV отчёт. Пример теста: безопасный файл с тестовой сигнатурой обнаруживается, помещается в карантин по подтверждению, восстанавливается без перезаписи другого файла. Вывод: основные пользовательские действия интегрированы и покрыты автоматизированными тестами; продукт остаётся учебным анализатором, не системным антивирусом с блокирующим драйвером.

Технологии: Python 3.10+, стандартная библиотека, psutil, Scapy, cryptography, PySide6 Essentials и pytest. Подтверждённые численные результаты испытаний приведены в [TESTING.md](TESTING.md) после финального прогона.
