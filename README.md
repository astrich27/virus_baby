# VirusWall

Учебное кроссплатформенное приложение для анализа файлов, процессов и сетевой активности; реализация лабораторных работ №3–6 в соответствии с техническим заданием и архитектурой работ №1–2 (документы `01_Техническое_задание.docx`, `06_Архитектура_и_техническая_документация.docx`).

Возможности (лабораторные №3–6):

- **Сигнатурный анализ** — база SHA-256/MD5-хэшей и байтовых шаблонов с резервной копией и откатом при повреждении; потоковый сканер файловой системы с исключениями (пути и маски `*.pdf.exe`).
- **Защита в реальном времени** — события файловой системы через `watchdog` (inotify / ReadDirectoryChangesW / kqueue) с политикой реакции `observe | notify | quarantine`; при недоступности watchdog — резервный опрос метаданных.
- **Эвристика** — взвешенные статические правила (двойное расширение, magic-заголовок, скрытый PE/ELF, опасные построчные конструкции, энтропия) с порогом чувствительности.
- **Поведенческий анализ** — снимки процессов psutil и настраиваемые шаблоны цепочек «родитель → потомок» в `config.json` (набор по умолчанию включает «офисное приложение запустило оболочку»).
- **Сетевой анализ** — соединения psutil, разбор IP/TCP/UDP/DNS метаданных Scapy, захват пакетов, агрегация потоков, разбор сохранённых PCAP-файлов, правила burst/повторов и локальные IOC-списки (IP и доменные суффиксы).
- **Карантин** — AES-256-GCM, лимиты (10 ГБ / 10 000 объектов / срок хранения), безопасное удаление с перезаписью, восстановление без перезаписи чужих файлов и повторное сканирование после восстановления.
- **Журнал** — JSONL с ротацией по 100 МБ, сроком хранения и хеш-цепочкой: подмена записей обнаруживается `events verify`.
- **Обновление баз** — подписанный манифест (Ed25519), атомарная замена и откат; повреждённая подпись отклоняется.
- **Самозащита (пользовательский уровень)** — единственный экземпляр (lock-файл), контроль сумм конфигурации и базы, события `tamper_detected`, права 0700/0600, команда `doctor` (самотестирование).
- **Отчёты** — JSON, CSV и **TXT** (формат приложения Г.6 ТЗ); события журнала содержат `event_id`, `engine_version`, `database_version`.
- Интерфейсы: CLI и нативное Qt-окно с системными уведомлениями о находках. Файлы не удаляются автоматически; карантин и восстановление требуют явного подтверждения.

Ограничения (честно фиксируются в [COVERAGE.md](COVERAGE.md)): нет системного драйвера-перехватчика операций ОС и служебного демона; автоматический карантин включается только явно (`policy = quarantine` + режим «на взводе»); эмуляции кода в эвристике нет; обновления применяются из локального подписанного манифеста (сетевая загрузка не реализована).

## Быстрый запуск

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m viruswall status
.venv/bin/python -m viruswall doctor
.venv/bin/python -m viruswall gui
```

В Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Команда `gui` открывает отдельное desktop-окно VirusWall на Qt; браузер и веб-сервер не используются. Данные по умолчанию хранятся в `~/.viruswall` (права 0700); другое расположение задаётся `--data-dir PATH`.

При первом запуске база содержит только безвредную тестовую сигнатуру EICAR. Примеры команд:

```bash
python -m viruswall scan /путь/к/файлу --report report.txt
python -m viruswall signature add-pattern <hex-шаблон> Lab.Pattern
python -m viruswall signature add <sha256> Lab.Sample --md5 <md5>
python -m viruswall realtime /каталог --arm          # защита в реальном времени
python -m viruswall pcap capture.pcap                # разбор сохранённого захвата
python -m viruswall update update.json               # применение подписанной базы
python -m viruswall quarantine put ФАЙЛ --yes --remove-original
python -m viruswall quarantine list
python -m viruswall quarantine delete <id> --yes
python -m viruswall events --verify                      # целостность хеш-цепочки
python -m viruswall doctor
python -m viruswall --help
```
