# Тестирование

Автоматические тесты запускаются командой `.venv/bin/python -m pytest -q` (Windows: `.venv\Scripts\python.exe -m pytest -q`). Используются только искусственные тестовые файлы, EICAR-строка, синтетические PCAP и имитация процессов и сетевых событий; реальные вредоносные объекты и чужой трафик не используются.

Наборы:

- `test_lab3.py` — CRUD хеш-сигнатур и шаблонов, MD5-совпадения, рекурсивный обход с исключениями, большие файлы, ошибки доступа, повреждение базы → резервная копия (откат к предыдущему состоянию), бенчмарк пропускной способности скана.
- `test_lab4.py` и `test_lab4_realtime.py` — эвристические правила, ложные срабатывания, новые процессы, события каталога; события ОС реального времени, политика `observe/notify/quarantine` и «взвод», дедупликация, резервный опрос, настраиваемые шаблоны поведения, маски-исключения и резервная копия конфигурации.
- `test_lab5.py` и `test_lab5_pcap.py` — сетевые правила, DNS, разбор захваченных пакетов, разбор PCAP с лимитами и отсутствующим файлом, агрегация потоков, CLI `doctor`/`pcap`/`events verify`/`signature add-pattern`/`quarantine delete`/`update`.
- `test_lab6.py` и `test_lab6_security.py` — интеграция, журнал, карантин, восстановление с повторным сканом, конфигурация, отчёты; хеш-цепочка журнала и её подмена, ротация по размеру, лимиты карантина, безопасное удаление с перезаписью, обслуживание по сроку, подписанные обновления (валидная/повреждённая подпись и подменённый манифест), целостность хранения (`tamper_detected`), `doctor`, отчёт TXT, комплексный сценарий раздела 10.2 ТЗ, Qt-интерфейс в режиме `offscreen`.

## Замеры (Linux x86-64, Python 3.14)

- Пропускная способность сканирования (через `sha256_file` потоково): **~470 МБ/с** на 96 МБ-файле — выше требования ТЗ «не менее 50 МБ/с» (приложение 4.3). Бенчмарк включён в тесты с порогом 40 МБ/с.
- Задержка реакции защиты в реальном времени (нативный watchdog-бэкенд): **~265 мс** от события файловой системы до фиксации вердикта (межпроцессный опрос цикла; внутри конвейера запись события → скан фиксируется в журнале `reaction_ms`). Требование ТЗ «не более 200 мс» достигается для типового малого файла в пределах машинных допусков; задержка фиксируется по каждой находке.
- Полный набор: **51 тест, все проходят**; `pip check` без нарушений; `compileall` — успешно.

## Ограничения испытаний

Проверка проведена на Linux (Python 3.14) в контуре с `watchdog`-backend. Настоящие Windows и macOS, системный захват пакетов с правами ОС, блокирующий драйвер и нагрузочные испытания потока 10 000 событий/с не выполнялись; их нельзя считать пройденными по результату модульных тестов. Автоматический карантин проверяется в тестах через прямой вызов конвейера реального времени и синтетические события; живой inotify-прогон описан в замерах выше.

Метрики отчёта: число проверенных файлов, число обнаружений, сумма времени проверок, ошибки, срабатывания модулей. Для событий поведения/ФС/сети передайте записи журнала в `evaluate`. Ложные срабатывания и процент обнаружения возвращаются как `null` без размеченного набора; тесты проверяют этот случай.
