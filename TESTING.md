# Тестирование

Автоматические тесты запускаются командой `.venv/bin/python -m pytest -q` (Windows: `.venv\Scripts\python.exe -m pytest -q`). Используются только искусственные тестовые файлы и имитация процессов и сетевых событий; реальные вредоносные объекты и чужой трафик не используются.

Наборы: `test_lab3.py` проверяет CRUD сигнатур, SHA-256, рекурсивный обход, исключения, большие файлы и ошибки; `test_lab4.py` — эвристические правила, снижение ложных срабатываний, новые процессы и события каталога; `test_lab5.py` — сетевые правила, DNS и разбор пакетов; `test_lab6.py` — интеграцию, журнал, карантин, восстановление, конфигурацию, отчёт и интерфейс.

Проверено в среде macOS, Python 3.14.7: `.venv/bin/python -m pytest -q` — **19 passed**; установка `.venv/bin/python -m pip install -e '.[test]'` успешна; `compileall` и `pip check` успешны; CLI `status` и `interfaces` запускаются. Проверка Qt в режиме `offscreen` создала нативное окно, запустила сканирование и получила результат в таблице. Команда `gui` также открыла обычное окно в графической сессии macOS; завершение по Ctrl+C прошло без ошибки. Просмотр соединений в этой изолированной среде запрещён ОС (`PermissionError`), приложение сообщает об этом без аварийного завершения.

Проверка на настоящих Windows и Linux, системный захват пакетов с правами ОС и нагрузочные испытания не выполнялись; их нельзя считать пройденными по результату модульных тестов.

Метрики отчёта: число проверенных файлов, число обнаружений, сумма времени проверок, ошибки и число срабатываний модулей. Для поведения, файловой системы и сети передайте в `evaluate` события из журнала. Ложные срабатывания и процент обнаружения возвращаются как `null`, если тестовый набор не размечен; тесты проверяют этот случай.
